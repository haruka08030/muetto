# 要件定義書

最終更新: 2026-08-24 / ステータス: v1 ドラフト合意済み

## 1. サービス定義

### 1.1 一言で

試香の記憶をデジタル化し、蓄積した評価から「自分の好きな香料・苦手な香料」を客観化して、
次の1本の失敗を防ぐパーソナル香水管理アプリ。

### 1.2 解決する課題

| ユーザーの課題 | 本アプリの解決 |
|---|---|
| 店頭で試した香りを覚えていられない。ムエットは捨ててしまう | 試香ログとして写真・メモ・評価つきで一元保存 |
| ネットで香水を買うと失敗する。自分が何を好きなのか言語化できていない | 高評価/低評価ログを香料・香調で交差分析し、好み・苦手を自動抽出 |
| 気になる香水を「現品で買う」か「少量試す」か迷い、探すのが面倒 | EC／サブスクへの導線を用途別に提示 |

### 1.3 Vivino との対応関係

参照モデルは Vivino（ワイン）。

| Vivino | 本アプリ |
|---|---|
| ラベル撮影で銘柄特定 | ボトル／箱の OCR 撮影で製品特定 |
| ワイン DB（品種・産地） | 香水 DB（香料ノート・香調アコード） |
| セラー（所持ワイン） | マイコレクション（所持香水・残量） |
| テイスティングノート | 試香ログ |
| Taste Profile | 好み傾向分析（好き／苦手な香料） |
| Matches for you | 類似香水レコメンド |
| 購入リンク・価格比較 | EC ＋ サブスク（カラリア等）導線 |
| コミュニティ評価・フォロー | **v1 では実装しない**（v2 以降） |

## 2. スコープ

### 2.1 v1 に含む

- 認証・オンボーディング
- 香水マスタ DB と検索（テキスト検索・フィルタ）
- カメラ OCR による香水特定
- 香水詳細（ノートピラミッド・香調・好み適合度）
- 試香ログの記録・編集・一覧
- マイコレクション（所持品・残量管理）
- ウィッシュリスト
- 好み傾向分析ダッシュボード
- 類似香水レコメンド
- ユーザーによる香水の新規登録・修正提案（未検証フラグ運用）
- 購入導線（EC／サブスク）とクリック計測基盤

### 2.2 v1 に含まない（v2 以降）

- コミュニティ機能（他ユーザーの評価閲覧、レビュー、フォロー、タイムライン）
- 協調フィルタリングによるレコメンド
- 有料プラン・課金
- 専用の管理画面 UI（v1 は Supabase Studio ＋ SQL で運用代替）
- 多言語 UI（スキーマ側のみ将来対応可能な設計にする）
- 試香ログにおける「時間経過ごとの個別メモ」（トップ／ミドル／ラストを個別に記録する機能）
  - **香水マスタ側のノートピラミッド情報（トップ／ミドル／ラストの香料構成）は v1 に含む。**
    v1 で見送るのは「ユーザーが時間経過ごとに個別のメモを残す」機能のみ。

## 3. 前提・確定事項

| 項目 | 決定 | 根拠 |
|---|---|---|
| プラットフォーム | Flutter（iOS / Android） | 操作性・UI の美しさを重視。両 OS 同一の描画、`google_mlkit_text_recognition` の成熟度、`fl_chart` によるグラフ表現 |
| バックエンド | Supabase | Postgres の交差集計が好み分析と相性が良い。Auth / Storage / Edge Functions が一体 |
| 香水 DB 調達 | スクレイピング ＋ ユーザー投稿 | [docs/data-ingestion.md](data-ingestion.md) 参照 |
| ユーザー投稿の運用 | 即時反映 ＋ `is_verified = false` フラグ | 投稿者の体験を止めず、検索表示で品質を担保 |
| 想定ユーザー | 一般公開・マルチユーザー | — |
| 画像認識 | オンデバイス OCR（ML Kit） | ランニングコストゼロ。読めない場合はテキスト検索へフォールバック |
| 市場・言語 | 日本中心・日本語 UI、多言語化を見据えたスキーマ | — |
| 収益 | 導線と計測は v1 実装、アフィリエイト提携は後回し | リンクをテンプレート方式で保持し、提携後に ID を差し込むだけで有効化 |

## 4. ユーザーとユースケース

### 4.1 想定ユーザー

- **メイン**: 香水を年に数本購入し、店頭やサブスクで日常的に試している 20〜40 代。
  好みは漠然と自覚しているが言語化できていない。
- **サブ**: 所持数が 10 本を超え、在庫と使用状況を把握しきれなくなっている層。

### 4.2 主要ユースケース

1. **店頭での試香**（最重要・最頻出）
   - 百貨店の売り場でムエットを受け取る → その場でアプリを開き、ボトルを撮影 → 候補から選択 →
     点数とメモを入力 → 保存。**所要 30 秒以内、電波が悪くても完了できること。**
2. **帰宅後の振り返り**
   - その日のログを見返して補足メモを追記、「買いたい」フラグを立てる。
3. **購入前の意思決定**
   - 気になる香水の詳細を開き、好み適合度と苦手香料の警告を確認 →
     サブスクで試すか現品を買うかを選び、外部サイトへ遷移。
4. **定期的な自己分析**
   - ダッシュボードで好き／苦手な香料の傾向を確認し、レコメンドから次に試すものを決める。
5. **在庫管理**
   - 所持香水の残量を更新し、使い切りそうなものを把握する。

## 5. 機能要件

### 5.1 認証・オンボーディング

- メール＋パスワード / Sign in with Apple / Google サインイン
  - App Store 審査要件により、他のソーシャルログインを実装する場合 Apple は必須。
- 未ログインでも香水の検索・詳細閲覧は可能。ログ保存の時点でサインアップを促す。
- オンボーディングで「好きなブランド」「好きな香調」を各 3 つまで選択。
  - 好み分析のコールドスタート緩和に使用する（初期プロファイル）。
  - スキップ可能。

### 5.2 香水検索

- **テキスト検索**: ブランド名・製品名を横断。日本語名／英語名／原語名／別名（synonyms）すべてを対象。
  - 表記ゆれに対応するため `pg_trgm` によるあいまい一致を併用する。
- **カメラ OCR 検索**: 詳細は 5.3。
- **フィルタ**: 香調カテゴリ / 香料 / ブランド / 賦香率（EDC・EDT・EDP・Parfum） / ターゲット性別 / 発売年
- **ソート**: 関連度 / 好み適合度 / 新着
- 検証済みデータを上位に表示し、未検証データは下部に分離して「未検証」バッジを付す。
- 0 件の場合は「この香水を登録する」導線を表示する。

### 5.3 カメラ OCR 検索

1. カメラでボトル／箱／テスターラベルを撮影
2. オンデバイス OCR（ML Kit、ラテン文字＋日本語）でテキスト抽出
3. 抽出文字列を正規化（大文字化、記号除去、`EAU DE PARFUM` 等の賦香率トークン分離）
4. ブランド名・製品名の候補にあいまい一致でマッチングし、**候補を複数カードで提示**してユーザーが選択
5. 一致しない場合は、抽出文字列をプリセットした状態でテキスト検索画面へフォールバック

**設計上の注意**: 意匠化された筆記体ロゴは OCR で読めないケースが多い。
「読めなかったときにストレスなくテキスト検索へ落ちる」ことを品質の基準とする。
将来 VLM によるフォールバックを追加できるよう、認識処理は差し替え可能なインターフェースの背後に置く。

### 5.4 香水詳細

- ノートピラミッド（トップ／ミドル／ラスト）の可視化
- 香調アコードの構成比バー
- 賦香率、発売年、ブランド、ターゲット
- **好み適合度スコア**（例:「あなたの好みと 87% 一致」「苦手なアニマリック系を含みます」）
  - 分析に必要なログ件数に達していない場合は非表示とし、必要件数を案内する
- 自分の試香ログ一覧（複数回試した履歴を時系列で表示）
- アクション: 試香ログを書く / 所持登録 / ウィッシュリスト追加 / 購入導線
- 未検証データには「情報が未確認です・修正を提案する」バッジ

### 5.5 試香ログ

記録項目:

| 分類 | 項目 | 必須 |
|---|---|---|
| 評価 | 総合評価 **1.0〜5.0（0.1 刻み）** | ○ |
| 日時 | 試香日 | ○（デフォルト当日） |
| メモ | 自由記述メモ | |
| 写真 | 複数枚（ムエット／ボトル／店頭） | |
| 試香方法 | 店頭ムエット / 肌 / サンプル / 所持品 | |
| コンテキスト | 着用シーン（仕事・デート・日常・夜・特別な日…複数選択） | |
| | 季節（春・夏・秋・冬、複数選択） | |
| | 気温帯（寒い / 涼しい / 温暖 / 暑い） | |
| 香りの性質 | 持続時間（1〜5 の整数） | |
| | 拡散力／シリラージ（1〜5 の整数） | |
| 判断 | 「買いたい」フラグ | |

**評価スケールの入力 UX**:
星をタップすると整数値（1〜5）が即入力され、そのまま横にドラッグすると 0.1 刻みで微調整できる。
店頭での高速入力（タップ 1 回）と分析解像度（0.1 刻み）を両立させる。

**その他の要件**:
- 所持していない香水にもログを付けられる（お試しメモ＝ウィッシュ／テストリストを兼ねる）
- 同一香水に対して複数回のログを記録できる
- **オフライン下書き**: 端末ローカルに保存し、オンライン復帰時に自動同期。写真も含む
- 「買いたい」フラグを立てるとウィッシュリストへ自動追加

### 5.6 マイコレクション（所持品管理）

- 所持登録項目: 入手形態（現品 / 分け・デカント / サンプル / サブスク便 / ギフト）、
  容量(ml)、価格、通貨、購入日、購入チャネル、残量(%)、ステータス（使用中 / 使い切り / 手放した）
- 残量はスライダーまたはボトルの目測バーで更新
- 残量更新の履歴から使い切り時期を簡易推定して表示（v1 は線形推定で可）
- サマリ: 所持本数、総額、平均評価

### 5.7 好み傾向分析ダッシュボード

- 好きな香料 TOP10 / 苦手な香料 TOP10（信頼度＝サンプル件数を併記）
- 香調カテゴリ別のレーダーチャート
- 季節別・シーン別の傾向
- 条件付き傾向の提示（例:「ローズ系は好きですが、ウードと組み合わさると評価が下がる傾向があります」）
- **分析根拠を必ず開示する**（例:「この判定は 8 件の高評価ログに基づきます」）。ブラックボックスにしない
- ログ件数が閾値未満の場合は「あと N 件で分析が始まります」と進捗を表示

アルゴリズムの詳細は [docs/preference-algorithm.md](preference-algorithm.md) を参照。

### 5.8 レコメンド

- 未試香の香水から、好みベクトルとの類似度上位を提示
- **推薦理由を必ず併記**（例:「あなたが高評価のイリス・パウダリー系を含みます」）
- 苦手香料を含む場合は減点し、警告を表示
- 各カードから「サブスクで試す」「現品を買う」に直接遷移できる

### 5.9 ユーザーによる香水登録・修正提案

- 登録項目: ブランド（既存選択 or 新規）、製品名（日本語／英語）、賦香率、発売年、
  ノート（トップ／ミドル／ラスト）、香調、画像
- 投稿は**即時に DB へ反映**し、`is_verified = false` を付与する
- 検索結果では検証済みを優先し、未検証はセクションを分けて表示
- 既存データの修正提案は `perfume_edit_suggestions` に蓄積し、承認時に本体へマージ
- v1 の承認オペレーションは Supabase Studio ＋ SQL で行う（専用管理 UI は v2）

### 5.10 購入導線と計測

- 販売チャネルマスタ（公式ショップ / Amazon / 楽天 / カラリア等のサブスク）を持つ
- 香水ごとに販売リンクを紐付ける
- **リンクはテンプレート方式**で保持する（`{affiliate_id}` を後から差し込むだけで提携を有効化できる）
- タップをクリックイベントとして記録し、成果測定・提携交渉の材料とする
- v1 時点では素のリンク、または各サイトの検索結果 URL で動作させる
- 用途別に導線を出し分ける: 「少量試す（サブスク）」／「現品を買う（EC・公式）」

## 6. 非機能要件

| 分類 | 要件 |
|---|---|
| オフライン | 試香ログの下書きを端末に保存し、復帰時に自動同期。閲覧済み香水をキャッシュ |
| 性能 | 検索結果の初回表示 1 秒以内 / OCR 認識 2 秒以内 / アプリ起動 2 秒以内 |
| 画像 | Supabase Storage。アップロード前にクライアント側でリサイズ・圧縮（長辺 1600px 目安） |
| セキュリティ | 全テーブルで RLS を有効化。クライアントに配置する鍵は anon key のみ |
| プライバシー | 試香ログは非公開がデフォルト。将来の公開機能に備え `visibility` カラムを最初から持つ |
| 計測 | クリックイベントと主要導線のファネルを計測 |
| アクセシビリティ | 動的フォントサイズ対応、コントラスト比 WCAG AA |
| 対応 OS | iOS 15 以上 / Android 8.0 (API 26) 以上 |
| 多言語 | v1 は日本語 UI のみ。文字列は最初から i18n リソース経由で参照する |

## 7. リスクと対応

| # | リスク | 影響 | 対応 |
|---|---|---|---|
| 1 | 香水マスタ DB の質と量の確保・維持コスト | 高 | スクレイピングによる初期構築 ＋ ユーザー投稿で継続的に拡充。詳細と留意点は [docs/data-ingestion.md](data-ingestion.md) |
| 2 | OCR が意匠化ロゴを読めない | 中 | テキスト検索へのフォールバックを主導線として設計。将来 VLM 追加の余地を残す |
| 3 | コールドスタート（ログ 0 件では分析できない） | 中 | オンボーディングでの好み申告と、分析開始までの進捗表示でつなぐ |
| 4 | 好み分析が「当たっていない」と感じられる | 中 | 根拠の全面開示、サンプル件数による信頼度表示、少数サンプルのベイズ補正 |
| 5 | アフィリエイト提携の審査に時間がかかる | 低 | リンクをテンプレート方式にし、提携前でも導線として機能させる |
